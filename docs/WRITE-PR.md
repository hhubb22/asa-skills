# PR/MR 材料

`write-pr` 为已有修改准备正式 message，按需要生成 HTML 审核说明。它可以在 code-review 后使用，也可以直接更新指定 PR/MR 的描述。

## 项目约定

在过程区的 PROJECT.md 中填写 PR/MR 模板路径或可访问链接、输出语言、说明格式偏好和附件位置。优先沿用项目模板，没有模板时使用 skill 的通用格式。公司模板由项目配置引用，公共 skill 只提供通用材料。

## 使用

```text
用 write-pr 为当前修改写 MR 描述，按项目模板填写，只要正式 message。
用 write-pr 解释这个跨模块改动，生成 PR.md 和给审核者看的 REVIEW.html，不创建远端 PR。
用 write-pr 更新已有 PR 的描述，检查说明是否对应当前 head；按已有授权更新远端。
```

简单改动的正式 message 可以很短。HTML 适合展示状态流转、调用关系、前后行为和审阅重点；用户显式要求 HTML 时照常生成。

## 材料与证据

文件默认保存在过程区。两份材料对应同一提交区间或工作区快照；未跟踪内容单独纳入范围，跨会话材料记录差异摘要和指纹。代码变化后核对解释及验证记录的基线。

测试结果写明实际命令、环境和覆盖限制。外部测试报告、需求级别或关联编号缺失时保留待补项。HTML 中的代码片段、图示与审查发现都能追到来源；生成后实际打开检查布局和链接。没有渲染能力时明确标记尚未确认的部分。

正式 message 使用目标读者能打开的审核说明链接。尚未上传的本地文件在交付说明中列出；上传、分享和远端 PR/MR 的创建或更新按已有授权执行。
