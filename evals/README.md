# 行为试跑

本目录提供 33 个合成行为案例（22 个开发案例、11 个保留案例）、一组触发测试和两个小型文件夹。它们是验收输入，不是已经运行的评测结果。没有硬编码关键词路由器，也没有伪造的模型分数。

## 触发测试

`triggers.json` 为每个 skill 准备 5 条应当触发和 5 条看似相关、但应当去往别处的说法（括号内为期望去向）。在目标宿主中逐条输入，记录实际选用的 skill，再与期望对比。

漏触发说明 description 缺少使用场景或关键词；误触发说明 description 范围过宽，或与相邻 skill 的边界不清。修改 description 后重跑全部条目，而不只是出错的那一条。

## 准备与运行

在库根目录执行：

```bash
python3 tools/prepare_eval.py --split dev --out .local/eval-dev
```

每个案例有 task.md、workspace/ 和 evaluator.json。只把任务及给定上下文交给待测 Agent，将 workspace 作为任务目录；不要将 evaluator.json、cases.json 或保留集作为待测上下文。可使用宿主隔离权限进一步限制访问。文本情景测试中的“假设工具”需在宿主侧实际配置或按模拟说明评价，不能算真实集成测试。

建议先在 Codex 或 Pi 的真实会话试跑小修复、实施、审查和交接，再跑其他边界案例。记录实际模型、宿主版本、工具权限、skills 哈希、任务记录、差异和测试结果。自然语言可先直接调用或按任务匹配，跨步骤任务再显式使用 work。

rule-query 文件夹含有故意的 bug；初始三项测试应有两项失败。请仅在复制出的 workspace 中修复，保留原样本作为对照。该文件夹不属于本库脚本单元测试套件。

## 比较候选改动

技术写作约定的句子表达改动尚未进行行为试跑。后续用相同材料分别生成行为规格与技术设计，比较改动前后的主语、动作、条件和结果是否清楚，是否减少无信息的开场预告和名词化表达，同时检查简化句子后是否仍保留因果关系、必要限定和证据。评价表达是否准确、易读，不按短句数量或主动语态比例评分。

使用开发样本提出补丁，再在相同条件的新工作区比较基线与候选。保留样本只用于检查回归；反复用于调参后需要补充新的保留样本。无法控制条件时标记 inconclusive。

评估目标、权限、表达和验证，而不是工具调用数。允许小任务无 skill、无缺陷审查、没有修改建议的 doctor 报告。保存证据后才将 evaluator.json 中的 not_run 改成 passed/failed/inconclusive。

不要在模型未运行时填写通过率。tools/prepare_eval.py 只准备文件，不发起 API、宿主进程或后台工作。真实输出含敏感信息时留在被忽略目录，提交前人工脱敏。
