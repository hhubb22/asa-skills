# Code review

审查真实差异，分别检查工程正确性与需求符合性。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。基线不明确或有工作区修改时阅读 [范围规则](references/diff-scope.md)；输出参考 [发现标准](references/findings.md)。

## 确定范围

优先使用用户指定的提交、分支、PR 或工作区。获取对应差异、提交清单和相关上下文。代码评审既可发生在提交后，也可包含暂存、未暂存与未跟踪文件；明确实际覆盖，不把 `HEAD` 差异冒充全部工作区。

读取已存在的项目审查规则，例如 REVIEW_GUIDE.md，以及该差异涉及的规格/issue/契约。文档名称不固定。没有规格仍然检查正确性，但将需求符合性标为受限，不发明需求。

## 两条检查路径

工程路径关注能造成实际影响的生命周期、并发、错误处理、兼容性及项目约束；不重复格式检查器的工作，不用通用重构偏好要求无关重写。

需求路径检查遗漏、错误实现、越界行为和验证缺口。对规格与代码的冲突核查证据，不假定任何一方永远正确。

复杂差异可以隔离两条路径并行审查；小差异在同一会话中检查即可。合并结果时核验、去重，保留类别与证据；不能为配额制造发现。

## 交付

每项发现给出位置、触发条件、影响、依据和严重性。区分可证实缺陷、待确认风险与非阻塞建议；测试缺失不自动等于实现错误。没有发现则明确说明检查范围及局限。

默认不改代码、不写 GitHub 评论、不更改标签。当前请求明确包含修复时，按授权修复并复验；只审查时即使建议很明确也不代替用户实施。
