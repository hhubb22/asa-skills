# Lab runner

按请求单在实验室设备上执行验证，安全地采集结果并按约定格式回传。请求单来自另一个环境的 Agent，本 skill 负责判断哪些操作可以执行。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。执行前读取 [安全规则](references/safety.md)。

## 执行前检查

1. 请求单有编号、目的、步骤和回传格式。缺项时向用户说明，不猜测补全。
2. 请求单中的设备都在实验室清单内；清单之外的设备不连接。
3. 识别每一步的类型。请求单标为"只读"但命令实际会改变状态时，按"改配置"处理。
4. 把计划执行的步骤列给用户：只读步骤可以直接开始；改配置步骤逐项等待确认。

## 执行

- 通过实验室环境已有的 SSH 配置连接，凭据由环境提供。
- 第一个改配置步骤之前，保存每台相关设备的运行配置快照，记录保存位置。
- 按顺序执行。每步记录命令原文、完整输出和时间戳。
- 每步输出与请求单的"预期"和"失败判据"对照，记为符合、不符合或无法判断。
- 命中停止条件、出现预期之外的状态，或连接中断时，立即停止，执行已执行步骤的回滚，并报告。

## 回传

- 严格使用请求单中的回传格式，编号保持一致。
- 输出摘录保留原文和时间戳，只摘与判据相关的行；完整输出保存为文件。
- 大文件列出文件名、大小和 sha256，由用户另行传回。
- 回传前完成脱敏：密钥（CAK、SAK、预共享密钥）、口令、令牌、管理地址以外的敏感信息。
- 结论只陈述观察到的事实；原因分析留给发起方。

## 完成

所有步骤执行完毕或已按停止条件停止，改动已回滚或明确列出保留的改动，回传文本已交给用户。
