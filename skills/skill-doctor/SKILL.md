# Skill doctor

维护本库及其路由，不追求更多规则或更高调用率。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。处理会话前读取 [证据与隐私](references/evidence-and-privacy.md)；评价与改动依据见 [维护准则](references/rubric.md)，报告使用 [模板](assets/REPORT.template.md)。

## 选择材料

只使用当前请求授权的会话与相关 skill/配置。明确给出的文件直接处理；“最近这些会话”无法定位时只问一次必要范围，不默认扫描用户目录。没有样本时可以审计指令结构，但不能声称行为改进已被证明。

需要整理导出的文本或 JSONL 时，可运行 [离线收集器](scripts/collect_sessions.py)。先查看 --help。收集器不调用模型、不上传、也不保证完全脱敏；云模型读取材料仍可能将其发送给模型提供方。按项目数据规则选择脱敏导出或本地模型。

## 诊断与修改

以具体任务目标、实际工具结果及产物为依据，找出误触发、漏触发、错误停顿、越权、文档空话、无效验证或交接失真。核对当时加载的指令版本；只有当前版本时标记版本不确定。

区分触发/加载问题、指令缺口、相互冲突、模型波动和工具/代码缺陷。相同 skill 出现于失败会话不证明它导致失败。已有正确规则被忽略时先查加载与冲突，不立即重复追加。

提出能解释失败、可复用且最小的修改，优先删除或替换。报告证据位置、拥有规则的文件、预期改变及可能副作用。分析期间只在报告目录生成 proposed 文件和 diff；不改正在使用的正式规则。

## 比较与交付

以原案例检查修正，用未参与修改的相邻案例检查回归；优先比较任务结果和越界/停顿，不优化调用次数。保持模型、工具、任务与代码基线可比；版本缺失或未重跑明确标记。

默认交付 Markdown 报告、候选补丁和验证状态。无法实际调用目标宿主时给出可执行的试验计划，不能把静态检查算成行为评测。没有足够证据支持修改也算有效结论。

用户明确要求应用候选补丁时，核对正式文件未漂移，保留回滚版本后应用并检查；不修改自己的验收标准来使本次评价通过。不设置定时任务，不因一次调用声称已经持续监控。
