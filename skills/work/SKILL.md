# Work

将目标推进到当前授权范围内的完成状态。这个入口是导航与衔接，不是每个任务的必经流程。

首次使用本库、且当前上下文尚无同版约定时，读取 [任务边界](references/operating-contract.md)。已经读取则沿用，不在每次切换时重复加载。

## 选择路径

从请求、已有讨论和实际产物确定交付物、范围与完成条件。明确的小修改可以直接完成；不要为使用 skill 而生成规格。需要专门方法时，从下表选择最少的相关项，只读取选中 skill 的正文。

| 当前需要 | 选用能力 |
|---|---|
| 查清机制、代码或标准中的事实 | `research` |
| 外部行为尚不明确，需要形成行为规格 | `write-product-spec` |
| 已有目标，需要决定模块、状态或接口如何改变 | `write-tech-spec` |
| 实施已有明确依据且已授权的设计 | `implement-specs` |
| 检查差异的正确性、项目约束或需求符合性 | `code-review` |
| 用户表示没理解当前解释或要求暂停重新对齐 | `wait-what` |
| 明确需要整理术语、概念关系或重要决策记录 | `domain-modeling` |
| 换会话、换目录或向另一个 Agent 交接 | `handoff` |
| 需要向知情者取得缺失事实或决定 | `to-questionnaire` |
| 用户要求复盘 Agent 行为、触发或指令质量 | `skill-doctor` |

通过宿主的 skill 发现/调用功能按名称定位；同名冲突先确认采用的来源。允许按宿主规则读取已安装的目标文件，不绕过显式调用限制。专项 skill 不再调用本入口。缺少目标 skill 时说明缺失，能直接完成的工作继续，不下载或安装未经请求的依赖。

## 保持连续

第一次选路用一句话说明即可，直接调用专项 skill 时无需绕回这里。保留当前任务的授权、事实与完成条件；已有设计不重写，已有回答不重问。

设计请求不会自动进入编码；实现并验证的请求应连续完成必要修改、检查和修复。当前范围内可自行选择实现细节；改变外部行为或重要责任边界时先给出证据与方案。

只把需要隔离上下文、能够独立交付的工作委派出去。结果交回后核对关键证据，不把多个 Agent 的同意当成正确性证明。

没有现成路径时，根据任务直接工作。调查缺陷可以形成有证据的假设和下一步实验，不为了满足流程强制创建可运行复现、规格或工单。

## 完成

用户要的结果已交付，必要验证已有结果，或阻塞原因和可评审决定已具体说明。不要用“路由完成”代替任务完成。
